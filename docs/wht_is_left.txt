1. University AWS allocation — university IT

Ask IT to provide:

- Access to the university AWS account through named accounts with appropriate permissions.
- An existing server allocation, or an EC2 instance: the project’s baseline is Ubuntu 24.04, t3.small, 30 GB gp3 storage.
- Confirmation that the allocated machine has sufficient spare capacity.
- A static public address or university-managed public entry point.
- A billing owner and confirmation of what the university’s AWS arrangement actually covers.

An existing AWS account does not automatically cover additional resource charges. Credits apply only to eligible charges under their terms. AWS credit guidance

2. Domain, networking and HTTPS — university IT / team

You need:

- An approved address, such as idealab.reva.edu.in.
- Its DNS record pointing to the allocated server.
- Public access on ports 80 and 443.
- SSH restricted to authorised university/VPN addresses.
- Ports 3001 and 27017 kept private.
- nginx configured for the actual domain.
- An HTTPS certificate, automatic renewal, and a renewal check.

The nginx template exists; installing it alone does not configure the certificate.

3. Real Microsoft sign-in — university IT

Replace the mock with a university-owned Microsoft Entra application:

- Tenant ID → MS_TENANT_ID
- Application ID → MS_CLIENT_ID
- New client secret → MS_CLIENT_SECRET
- Approved web callback:
  https://<domain>/api/auth/microsoft/callback
- Institutional consent/access approval as required by REVA’s tenant policies.
- A named owner and reminder for secret renewal.

Remove the local MS_AUTHORITY override. Do not run mock:microsoft on production.

4. Real Google sign-in — team / institutional account owner

If external visitors will use Google:

- Create a university-owned Google OAuth web application.
- Configure its consent screen and required publishing/verification steps.
- Register:
  https://<domain>/api/auth/google/callback
- Set fresh GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET.
- Remove the local GOOGLE_AUTHORITY override.

Google sign-in can remain disabled if you choose not to offer it.

5. Working email — university IT / team

Email is needed for account verification and password resets:

- Verify the sending domain/address in Amazon SES.
- Configure the supplied DNS verification/DKIM records.
- Obtain SES production access in the selected region.
- Set the real EMAIL_FROM and AWS_REGION.
- Attach an EC2 IAM role permitting the required SES operations.
- Test delivery to real REVA and external mailboxes.

SES sandbox access limits delivery to verified recipients. SES production-access requirements

For Docker to obtain instance-role credentials through IMDSv2, configure the appropriate metadata options; AWS recommends a hop limit of 2 for container environments. AWS container guidance
